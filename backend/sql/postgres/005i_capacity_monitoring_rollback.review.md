# 005i PostgreSQL 容量、监控阈值与自动回滚信号评审

评审日期：2026-08-26（Asia/Shanghai）

状态：`CANDIDATE`。本批不修改主服务，不开启 full 模式，不迁移真实用户数据。

## 容量门禁

全量模式在能力清单未来满足后，仍必须同时证明：

```text
应用连接上限 = 最大实例数 × 每实例连接池上限
应用连接上限 <= 声明的应用连接预算
声明的应用连接预算 + 运维保留连接 <= 数据库 max_connections
```

实例与池上限需要两组值：发布声明值和控制台独立复核值。两组不一致时失败关闭，不能只修改环境变量后宣称控制台已核对。

## 运行信号

005i 只产生安全的 `continue`、`hold`、`rollback` 信号，不在应用进程内调用云平台发布接口：

- 样本不足：`hold`，禁止扩大流量；
- 等待客户端、池饱和或连续 readiness 失败达到阈值：立即 `rollback`；
- 连接超时、事务失败、HTTP 副作用失败或身份失败率在最小样本数后达到阈值：`rollback`；
- 所有阈值均满足且样本充分：`continue`。

信号只返回固定原因码和计数，不返回连接串、SQL、身份、请求正文或错误正文。真正的自动回滚动作由 CloudBase 发布策略消费该信号，005i 云验必须验证阈值和信号，不能宣称已经完成平台动作联动。

## 失败关闭顺序

1. full 独立确认；
2. 37 方法最终能力清单；
3. 容量评审确认、控制台拓扑一致及预算公式；
4. 回滚阈值独立确认；
5. 后续 005j–005m 数据、回滚、备份和预生产门槛。

当前能力清单仍为 `database_ready` 而非 `implemented_and_verified`，因此正常 full 请求继续先返回 `POSTGRES_FULL_CUTOVER_NOT_READY`。005i 不得通过批量修改能力字符串来绕过该门禁。

## 云验要求

1. 使用独立临时服务，正式 UserStore 保持 SQLite。
2. 从控制台取得实例/池上限，并通过`005i_capacity_preflight.review.sql`只读取得`max_connections`及聚合连接计数；不得把凭据写入证据。
3. 运行本地 cloud guard，证明缺确认、拓扑不一致、预算超限和缺阈值时联网前拒绝。
4. 云端只做 readiness 和连接池计数读取，不写业务数据。
5. 健康实值必须产生 `continue`；合成阈值快照必须产生 `rollback`。
6. 删除临时服务并证明实例归零。

- 数据迁移、稳定回滚制品、备份恢复和最终 Go/No-Go 分别属于 005j–005m。
