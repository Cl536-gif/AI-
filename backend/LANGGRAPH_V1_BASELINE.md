# LangGraph v1 基线

冻结日期：2026-08-05  
基线分支：`claude/diet-secretary-backend-075g7s`

## 基线用途

这一版作为当前可用的 LangGraph 对话流程基线。后续工作转向用户身份、长期档案、事件数据库、计算引擎、计划版本和长期记忆；发现新的对话问题时，再回到 LangGraph 做有测试保护的局部修改。

## 当前覆盖范围

- 六项饮食信息与食堂打饭方式的状态化采集。
- 用户同轮多项回答、补充、改口和待确认队列。
- 情绪优先回应，以及回答用户插问后恢复采集。
- 免费问答与长期规划分支、提醒频率说明和多条消息间隔。
- 第一版单餐方案、食堂替换、生活化分量和午晚餐/早餐边界。
- 长期规划后的身体数据、单位换算、异常值确认和经期信息采集。
- 开放菜名识别、口味推断确认、后续追加偏好不覆盖旧值。
- 方案发出后的局部问答，不重复档案或整份方案。
- 输出格式、长度、标点和产品真实性兜底。

## 已验证

2026-08-05 已运行本地确定性场景回归，包括场景18至30中的相关采集场景，以及场景33、37、39、40、42、43；全部通过。LangGraph 图可正常编译，`git diff --check` 通过。

## 仍需单独验证

- 依赖真实 DashScope/百炼模型的自然语言抽取与完整 HTTP 长对话，需要网络可用，并在涉及身体、经期等测试数据时取得明确授权后运行。
- 当前 MemorySaver 只适合本地测试，服务重启后会话状态会消失；它不是正式长期档案。
- 提醒目前是对话流程与测试话术，正式上线前仍需接入真实调度、用户身份和持久化系统。

## 后续修改规则

1. 对话话术与 LangGraph 节点可以继续迭代，但不得把完整助手回复作为用户档案。
2. 用户数据统一写入结构化数据契约，对话层只负责采集和呈现。
3. 每个新问题先增加可复现测试，再修改代码，并运行既有相关回归。
4. 数据字段发生变化时，必须同步更新抽取结构、校验、持久化迁移和测试。
5. 不提交 `node_modules`、`.env`、本地知识库原文、向量索引或评测报告。
