# 渠道接入可复用验证检查清单

## 1. 适用范围

本清单沉淀企业微信异步渠道在以下三轮验证中的经验，供后续企业微信、小程序、App 或其他消息渠道复用：

1. 崩溃恢复验证；
2. 正常流程回归；
3. 虚拟凭证协议联调。

清单用于证明“渠道适配层可靠地复用同一套业务和 LangGraph 能力”，不能代替各平台的官方协议核对、真实平台联调或正式发布审批。

## 2. 执行原则

- 渠道层只负责验签、解密、身份映射、快速确认、异步任务和出站格式转换；业务对话复用共享 LangGraph 调用层。
- 回调请求必须先持久化成功再返回成功确认，不能只把任务放进进程内存。
- 入站消息、图操作、业务副作用和出站消息分别使用稳定幂等键。
- “平台已接受请求”和“本地已记录发送成功”是两个状态，必须覆盖两者之间崩溃的场景。
- 正式渠道开关、测试白名单和真实凭证授权是三道独立门槛；通过自动化测试不自动打开正式渠道。
- 所有输出保存为 Markdown，包含命令、退出码、完整原始 JSON、关键断言数字、测试边界和未覆盖范围。
- 报告不得包含 Secret、Token、EncodingAESKey、access token、数据库密码、用户原话或完整知识库正文。

## 3. 开始前门禁

| 检查项 | 必须提供的证据 |
| --- | --- |
| 代码基线 | 固定 Git 提交、分支、工作区差异说明 |
| 渠道状态 | 正式开关默认关闭；测试环境启用方式明确 |
| 凭证保护 | 真实值只来自环境变量；`.env.example` 无真实值；`.gitignore` 覆盖 `.env` |
| 身份边界 | 渠道外部身份如何映射内部用户、是否允许匿名、跨渠道是否自动合并 |
| 幂等键 | 入站消息键、图操作 ID、业务副作用 ID、Outbox 请求 ID 的来源与唯一性 |
| 持久化 | 入站任务、checkpoint/receipt、Outbox 均为可恢复存储，不依赖单进程内存 |
| 网络边界 | 测试监听地址、允许的外网请求、白名单和超时限制 |
| 数据隔离 | 临时数据库或固定测试前缀；清理范围可证明且不会命中正式用户数据 |

## 4. 崩溃恢复：七个强杀点

每个场景必须真实启动独立 Worker 进程，并使用 `SIGKILL` 终止。禁止用抛异常、返回错误或手工改状态代替真实进程崩溃。

| # | 强杀位置 | 恢复时应依据的持久化事实 | 必须断言 |
| ---: | --- | --- | --- |
| 1 | 入队完成、尚未领取 | 入站任务存在、无图状态 | 最终模型调用 1；用户消息 1；副作用 1；Outbox 1；任务完成 |
| 2 | 取得租约、尚未进入图 | 任务租约过期、无图状态 | 新 Worker 可重新领取；最终各业务动作均为 1 |
| 3 | 中间 checkpoint 已写 | `checkpoint_incomplete` | 从 checkpoint 续跑；不得重复用户消息或模型副作用 |
| 4 | 图结果生成、receipt 未写 | `persistence_pending` | 恢复持久化阶段；不得从头无脑重跑 |
| 5 | receipt 已写、任务未更新 | `receipt_pending` | 根据 receipt 完成任务；业务副作用仍为 1 |
| 6 | Outbox 已写、尚未发送 | 图状态 `complete`、Outbox 待发送 | 只恢复发送；Outbox 行仍为 1 |
| 7 | 平台已接受、成功状态未落库 | 稳定出站请求 ID | 允许上游请求 2 次，但平台实际接受必须为 1 |

每个场景的报告至少给出：

- `childKillSignal`；
- 崩溃点持久化标记；
- 崩溃后图状态分类；
- 模型调用次数；
- 用户消息次数；
- 业务副作用次数；
- Outbox 行数；
- 上游请求次数；
- 上游实际接受次数；
- 最终任务状态。

通过标准：七个场景最终任务全部为 `completed`；模型调用、用户消息、业务副作用和 Outbox 均为 `1`；只有“平台已接受但本地未落库”场景允许上游请求为 `2`，但实际接受仍须为 `1`。

## 5. 正常流程回归

以下项目必须逐项输出具体数字：

| # | 回归项 | 最低断言 |
| ---: | --- | --- |
| 1 | URL/握手验证 | 正确签名 200；回显/挑战值匹配；非法 Token 被拒绝 |
| 2 | POST 验签与解密 | 合法消息入库 1；错误签名入库 0 |
| 3 | 快速确认 | 提交后返回平台要求的成功响应；响应体与耗时满足平台限制 |
| 4 | Worker 领取 | 领取 1；完成 1 |
| 5 | 开场、服务选择、定价、注销 | 每条确定性分支各有匹配与持久化断言 |
| 6 | 共享 LangGraph 链路 | LangGraph 调用 1；receipt 1 |
| 7 | access token 缓存 | 首次获取、缓存复用、失效刷新均有计数 |
| 8 | 平台长度限制 | 按 UTF-8 字节安全截断；不得产生替换字符 |
| 9 | 主动发送 | 尝试 1；平台接受 1 |
| 10 | 重复入站去重 | 回调 2；任务行 1；第二次仍返回协议允许的成功响应 |
| 11 | 同一成员顺序 | 第一条先领取；并发领取被阻塞；第二条随后领取 |
| 12 | 不同成员并行 | 同时领取至少 2；线程/会话彼此独立 |
| 13 | 渠道关闭隔离 | 路由不可用；Worker 0；网络请求 0 |

## 6. 虚拟凭证协议联调

虚拟平台必须通过真实 HTTP 请求与生产路由交互，但只监听本机回环地址，外部网络请求数必须为 `0`。

| # | 联调项 | 必须断言 |
| ---: | --- | --- |
| 1 | 正式闸门 | 生产开关关闭；真实凭证数 0；外网请求 0 |
| 2 | 回调握手 | 签名接受、AES 解密、挑战值返回全部匹配 |
| 3 | 非法协议输入 | 错误签名、接收方、应用 ID、非白名单成员全部拒绝且入库 0 |
| 4 | 加密 POST 快速确认 | HTTP 成功、空响应/规定响应、任务提交 1、后台完成 1 |
| 5 | 渠道开场与选择 | 开场、定价、选择持久化；未完成选择前不得提前启动图 |
| 6 | LangGraph—receipt—Outbox | 模型、业务副作用、任务、receipt、Outbox、身份和回复逐项计数 |
| 7 | token 缓存与虚拟上游 | token 获取、缓存复用、接收人和应用 ID 全部匹配 |
| 8 | 重复投递幂等 | 回调 2；任务 1；第二次 Worker 领取 0；模型和副作用仍为 1 |

## 7. 真实平台联调门槛

只有虚拟凭证联调全部通过并经单独批准后，才进入真实平台联调：

1. 确认合法、稳定、主体匹配的 HTTPS 回调地址。
2. 真实凭证仅进入部署环境变量，不进入命令输出或 Git。
3. 测试成员限制在明确白名单内。
4. 依次执行 URL 验证、真实入站消息、后台处理、主动推送。
5. 验证平台重试、重复 MsgId、token 失效与超时行为。
6. 记录平台可见结果与服务端脱敏计数，不记录明文密钥和用户内容。
7. 真实联调通过不等同于正式对外上线；上线仍需容量、监控、隐私、备案和人工批准。

## 8. LangGraph 与知识库质量门槛

渠道可靠性通过后，还必须独立验证业务效果：

- 同一个问题分别走原生接口、渠道接口和本地知识库对比接口，确认核心回答一致。
- 跑完完整信息采集状态机，确认不会因渠道重试重复推进节点。
- 进入 `generatePlan` 后检查知识库命中数量、来源和最终回复的事实一致性。
- 将“检索成功”和“回答正确”分开判定；返回 5 个片段不自动证明最终回答合格。
- 对未命中、低分命中、模型超时和格式护栏重试分别留测试用例。
- 每轮报告记录输入类别、状态迁移、命中库、片段数、人工结论和失败原因；用户内容必须脱敏。

## 9. 清理与暂停

- 清理只使用本轮固定 run ID、任务前缀或测试主体哈希。
- 清理前后分别记录任务、receipt、checkpoint、Outbox 和身份行数。
- 失败时先保存证据再清理，不得为了得到 PASS 修改数据库状态。
- 外部条件不满足时记录 `PAUSED` 或 `BLOCKED`，不得把“尚未执行”写成通过。
- 暂停期间保持正式渠道开关关闭，并确认没有残留公网入口、Worker 或定时任务。
