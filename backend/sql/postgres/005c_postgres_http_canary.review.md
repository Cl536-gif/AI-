# 005c PostgreSQL真实HTTP灰度与受控清理（审核稿）

状态：清理候选仅完成本地静态验证；当前稳定版本仍为SQLite。

## 1. 固定测试身份

真实HTTP只允许使用以下专用测试设备ID：

```text
005c0000-0000-4000-8000-000000000001
```

它符合应用UUID格式，但只用于005c。数据库脚本按应用相同的带命名空间SHA-256算法定位身份，不输出摘要或匿名用户ID。

## 2. 执行顺序

1. 在DMS执行只读preflight，必须返回`PASS,true,true,0`。
2. 以005a相同门禁创建单实例、池上限1的PostgreSQL灰度修订。
3. 检查health与ready均为HTTP 200。
4. 只发送一条`/api/chat-langgraph`请求，使用固定设备ID和不含个人资料的通用午餐问题。
5. 要求HTTP 200、匿名身份已解析、建议已记录、服务状态为free，且回答不编造既有档案。
6. 不发送第二条消息，不进行账号合并、订阅、经期或计划流程。
7. 立即恢复SQLite稳定修订。
8. 在DMS执行cleanup；必须证明HTTP建议曾持久化，随后返回身份、用户和建议零残留。
9. 再次执行preflight，必须重新返回固定身份不存在。

## 3. 清理安全边界

- 只通过固定设备摘要解析唯一用户；没有映射、多个映射或非匿名用户全部拒绝。
- 测试用户参与任何身份合并时拒绝自动清理。
- HTTP没有产生至少一条建议记录时，仍清理固定测试身份，但`http_advice_was_persisted=false`，005c验收不得通过。
- 每张表只使用精确`user_id`或固定摘要条件删除；禁止通配删除、TRUNCATE和DDL。
- 由DMS审核角色执行，不向业务`diet_app`增加删除权限或生产清理接口。
- 删除后在同一事务重新证明身份、用户和建议均为0，再提交。

## 4. 失败与回滚

任何HTTP 5xx、readiness异常、回答事实错误、持久化状态异常或清理断言失败，都立即停止。业务修订恢复SQLite；数据库清理脚本保持事务失败，不通过放宽条件来强行删除。若测试用户参与合并，转人工审核，不运行自动清理。

## 5. 本批不做

- 不使用真实用户或真实饮食资料。
- 不扩大到第二个实例或更多流量。
- 不把PostgreSQL设为默认Provider。
- 不把全量cutover门槛改为true。
