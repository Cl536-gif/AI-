# 用户身份与长期档案数据契约 v1

## 设计目标

对话层可以持续修改，但长期数据的含义保持稳定。系统不保存“助手说过的一整段话”作为档案，而是保存经过确认的结构化档案和带时间的事实事件。

## 四类数据

### 1. 用户身份 `users`

只保存匿名 `userId`、创建时间、最后活跃时间、时区和语言。身份表不直接存放饮食或健康详情。

### 2. 当前档案 `user_profiles`

保存当前有效的结构化快照，并带递增版本号。内容包括：

- 身体基础信息：年龄、身高、当前体重、目标体重、日常活动。
- 饮食基础信息：场景、食堂模式、每餐预算、口味、忌口、目标和运动基线。
- 经期记录状态：是否适用、是否启用；具体日期不放在快照中。

更新档案时不会丢掉旧版本，每次快照同时写入 `profile_revisions`。调用方可以用 `expectedVersion` 防止两个请求相互覆盖。

### 3. 长期事件 `user_events`

事件只追加，不直接修改历史：

- `meal`：正餐。
- `snack`：零食或加餐。
- `body_measurement`：体重等测量。
- `exercise`：运动类型、时长和设备估算消耗。
- `menstrual_period_start`：月经开始日期。
- `menstrual_symptom`：食欲、疲劳、腹胀、疼痛等实际变化。
- `check_in`：阶段反馈。
- `plan_interruption`：断联、旅行、生病或计划中断。
- `user_correction`：用户纠正旧记录。

需要纠错时新增事件，并用 `supersedesEventId` 指向旧事件。`idempotencyKey` 用于避免网络重试造成重复记录。

### 4. 授权记录 `user_consents`

长期档案、经期追踪和主动提醒分别记录授权状态。撤回授权通过新增 `revoked` 记录表达，不覆盖曾经发生的授权事实。

## 单位契约

进入数据层前统一标准化：

- 身高：厘米 `cm`。
- 体重：公斤 `kg`。
- 金额：人民币元。
- 时间：带时区的 ISO 8601 字符串。
- 设备热量：只作为设备估算值写进事件 payload，不直接等量补回饮食。

原始用户表达可以放在事件 payload 的 `rawText` 中用于审计，但不能代替标准字段。

## 隐私边界

- 经期日期和症状属于时间事件，不放在公开身份字段中。
- 不记录未确认的模型推断为事实。
- 对话线程 ID 不等于用户 ID；同一用户可以有多个线程。
- 当前 SQLite 是本地第一版实现，正式部署时可以迁移到 PostgreSQL/Supabase，但数据契约不变。

## 与 LangGraph 的后续接法

下一步新增一个明确的持久化边界：LangGraph 先输出“档案补丁”或“事件命令”，业务层校验后再调用 `userStore`。LangGraph 节点不能直接拼 SQL，也不能依赖某一句固定话术触发数据库写入。
