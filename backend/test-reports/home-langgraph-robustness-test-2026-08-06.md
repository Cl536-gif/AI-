# 首页 LangGraph 鲁棒性测试记录（2026-08-06）

## 测试目标

围绕真实用户可能出现的不同表达方式，重点检查：

1. 隐私政策口令、自然表达及错字是否能识别。
2. 首页身份是否与 V3 测试身份隔离。
3. 用户一句话提供多个字段时是否整体接收。
4. “哦对还有”是否追加而不是覆盖；“两个都是”是否保留新旧值。
5. 用户插问时是否先回答，再恢复未完成流程。
6. 信息有歧义时是否只确认一次，清晰信息是否直接保存。
7. 问题没问完或方案没生成时，是否会提前声称已有方案。
8. 身体数据单位、长期方案资格、经期信息顺序和14天体验启动时点是否正确。
9. 不同匿名用户的档案与事件是否相互隔离。

## 本轮发现并处理的问题

### 1. 经期采集提示缺少“暂时不方便提供”入口

- 结果：失败后已修复。
- 修复：提示中明确覆盖“目前没有月经或暂时不方便提供”的情况。
- 复测：通过。

### 2. 身体数据旧测试口径落后

- 现行规则要求年龄、身高、当前体重、平时活动情况四项基础数据。
- 旧测试只给前三项，却误称为“完整数据”。
- 处理：更新测试，不放松现行建档要求。
- 复测：通过。

### 3. 未生成方案时，简单回复“好的”触发虚假方案收尾

- 原错误：“那就先按上面的饮食搭配吃着哈”。
- 修复：只有当前状态明确存在已交付方案时才能使用方案收尾。
- 没有已交付方案时，不得声称“按上面的方案”。
- 复测：通过。

### 4. 首页读取到 V3 测试档案

- 原因：首页与 compare-v3 共用 `dietSecretary.deviceId`。
- 修复：首页改用独立的 `dietSecretary.home.deviceId`。
- 结果：刷新首页后自动建立干净的首页匿名身份，不再读取测试台虚构资料。

### 5. 历史档案冒充本轮原话

- 修复：引用历史资料时必须明确说“之前的档案里记录过”，禁止说“你刚才提到”。

### 6. 未回答运动，却在摘要中写成“暂不运动”

- 原因：模型生成的承接摘要会偶尔补出用户尚未回答的字段；状态层没有保存假值，但用户已经看到了错误事实。
- 修复：新增确定性检查。凡是“记下了/当前情况”类陈述，只允许出现已确认字段；命中未确认字段会重新生成，重试失败则使用安全模板。
- 复测：长期流程中，用户回答运动前不再出现“暂不运动”。

### 7. “哦对还有锅包肉”没有明确复述旧食物

- 原错误：回复只说“之前说的食物和锅包肉”，用户无法判断温州米面是否真的保留。
- 修复：追加确认必须明确列出旧值和新值，例如“之前记录的温州米面和新补充的锅包肉都会保留”。
- 复测：通过。

### 8. 经期日期分两轮提供时丢失第一轮日期

- 测试输入：先说“8月4号来的三个月”，再说“不规律，前一次大约5月4日”。
- 原错误：模型没有稳定提取第一轮的“8月4号”，造成重复追问。
- 修复：新增明确日期原文提取，跨轮累积“X月X日/号”；仍不把“来了三个月”解释成周期三个月。
- 复测：两条日期正确累积，进入下一阶段。

### 9. 未提供活动量却提前完成身体建档并报500

- 原因：真实模型曾在“20kg, 165cm 22岁”中自行补出活动量，系统因此误判资料完整；正式计算时才发现活动量不可用。
- 修复：活动量只有在用户原文出现“久坐、走动、站立、上课、通勤”等证据时才接收。长期规划的必填身体数据没补齐时，不得进入经期或启动14天体验，更不能让接口报500。
- 复测：确定性测试通过；真实流程加入“平时上课久坐”后正常完成。

## 已通过的对话状态测试

- 首页隐私说明、查看重点条款、等待用户继续。
- “继续”“好吧”“好的”“可以”“OK”“没有问题，继续”等继续表达。
- “隐私政策”“我想了解隐私条款”“隐私正策”“隐思条款”等表达。
- 清晰多字段整体接收，不拆成逐项机械确认。
- 同句多个维度进入待处理队列，不漏字段。
- 香蕉飞饼、煎饼等未预置菜名仍能作为口味回答处理。
- 小炒肉先根据菜品特点提出口味推断，再让用户确认。
- “还有甜的”追加到原口味，不覆盖。
- “哦对还有”按新增处理；“两个都是”保留新旧两个值。
- 用户确认时补充其它内容，同轮不会重复抽取或重复确认。
- “精气神”等目标表达可以归入整体状态目标。
- 用户明确提问时先回答，之后恢复原待办流程。
- 破折号、连续横线和用户可见英文有确定性拦截。
- 男性不能进入长期路径；女性继续完成长期建档；含糊性别不猜测。
- 身体数据位于经期数据之前；可疑身体数据要求确认。
- 未出方案时，简单确认不会再产生“按上面方案吃”的虚假回复。

## 已通过的数据与长期服务测试

- 匿名身份稳定映射，不同设备数据严格隔离。
- 数据库只保存设备标识摘要。
- 档案局部更新、版本历史与冲突保护。
- 事件追加、幂等去重、授权撤回和敏感数据隔离。
- 免费用户只能读取基础档案，不能写入长期事件或建立阶段计划。
- 经期授权撤回后，历史敏感信息立即退出模型上下文。
- 近期事件按发生时间稳定倒序。
- 公斤、斤、克、磅、厘米、米、英寸和年龄单位统一换算。
- 计算输入、公式版本、假设、结果与来源保留审计记录。
- 选择长期和完成资料不会提前计时。
- 第一份正式长期方案成功交付后才启动14天体验。
- 第13天续费提醒和第14天体验结束时间正确。
- 单餐反馈、一次零食或一次运动不会擅自改写长期计划。
- 计划中断只暂停，不会自动建立新版；恢复或重做必须由用户确认。

## 真实模型测试结果

已获得测试授权，使用完全虚构的人物资料调用当前配置的阿里云百炼模型。

### A. 十组多表达回归

结果：10组全部通过。

1. “女大学生/男大学生”不再被识别成“食堂”。
2. 用户中途提问会先回答，且不会输出破折号、连续横线或残留英文。
3. “精气神”可识别为整体状态目标。
4. 一句话回答多个维度时会逐项接收，不漏字段。
5. “小炒肉”会先推断偏辣，再请求确认。
6. 用户确认旧值时补充“还喜欢甜的”，会同时完成确认和追加。
7. “哦对还有”不会被误判为替换。
8. 未预置的新口味可由真实模型识别。
9. 身体数据必须先于经期信息完成。
10. 年龄、身高、体重的真实模型抽取正常。

### B. 女性长期方案完整流程

关键逐轮问答：

```text
用户：你好，我是女大学生，想减脂
秘书：自我介绍并询问食堂还是外卖。

用户：食堂 → 自选 → 小炒肉
秘书：识别食堂自选；对“小炒肉偏辣”先提出确认，不直接落档。

用户：对，另外也喜欢甜的
秘书：明确保留小炒肉、辣味和甜味，再询问预算；不再编造“暂不运动”。

用户：每顿20元左右 → 没有忌口，也没有已知过敏 → 每周跑步两次，每次四十分钟
秘书：六项完成后才说明免费问答与长期规划两种服务。

用户：我选择长期饮食规划 → 生理女性 → 每周一和周四晚上八点提醒我
秘书：确认长期资格和提醒安排；生成包含一拳杂粮饭、一掌小炒肉、一份时蔬的第一版具体方案。

用户：20岁，165厘米，现在55公斤，目标50公斤，平时上课久坐比较多，最近一个月体重没怎么变
秘书：完成身体数据建档，随后才询问经期。

用户：最近一次是7月20日开始，平时比较规律，经期前容易饿，也会有点腹胀
秘书：完成经期记录并正式建立第一阶段方案；此时才启动14天体验。
```

最终断言：六项均确认、长期服务状态正确、身体与经期顺序正确、首份方案确实含具体食物和生活化分量、14天体验没有提前启动、用户可见文本无禁用标点和英文。

### C. 焦虑开场、追加食物、异常体重、经期歧义完整流程

最终通过的关键逐轮问答：

```text
用户：我很焦虑
秘书：先共情、给出轻量解决方向和鼓励，再询问最基础的就餐场景。

用户：食堂 → 自选 → 温州米面 → 哦对还有锅包肉
秘书：明确说“之前记录的温州米面和新补充的锅包肉都会保留”，再确认酸甜口味。

用户：对 → 30 → 酸奶腹泻 → 上镜 → 不运动
秘书：恢复此前预算问题；依次记录预算、身体不适、目标、运动，全部完成后才进入服务选择。

用户：长期 → 生理女性 → 每隔两天
秘书：先校验长期资格，再安排提醒，随后交付第一版午晚餐方案并询问身体数据。

用户：20kg, 165cm 22岁，平时上课久坐
秘书：发现20公斤明显可疑，要求确认，不静默丢弃或自行改数值。

用户：80公斤
秘书：保留同轮已经识别的22岁、165厘米、久坐，只更正当前体重；之后进入经期问题。

用户：8月4号来的三个月
秘书：没有把“三个月”误记为周期长度，继续询问规律性和前次日期。

用户：不规律，前一次大约5月4日
秘书：跨轮保留8月4号和5月4日，完成记录并正式建立长期方案、启动14天体验。

用户：好的
秘书：只做简短方案承接，不再重复整份档案或完整方案。
```

最终结果：通过真实 HTTP 回归。

## 当前结论

- 本轮所有已经建立自动断言的回归均通过。
- 两条真实长对话均走通，测试中暴露的四个新增问题均已修复并加入防回归测试。
- 不能宣称自然语言系统未来“绝对零错误”；当前降低错误率的方法是把高风险事实判断、状态推进、单位换算和体验计时放到确定性代码与测试中，模型只负责自然表达。
